> 技术栈：SQL / MySQL 8  
> 验证范围：已修正静态可识别问题；本机无 MySQL，未做数据库运行验证

## 项目内容

压缩包实际为数据库原理实验，原放在“最优化方法”目录。按内容纠正归类，不杜撰最优化算法。原数据备份不发布；初始化脚本仅包含结构和明确虚构的示例数据，权限练习使用示例口令。

## 执行顺序与已修复问题

MySQL 8.0.16+。先在独立练习环境执行 `sql/2.a-建立基本表的结构.sql`，脚本仅重置专用 `undergraduate_orders_demo` 数据库中的实验表。客户名称、联系方式、地址已全部替换为虚构示例，业务编号显式设置，避免依赖不可靠的自增值查询触发器。

1. 初始化后，先运行 `3.*` 查询；可按需练习 `2.b` 修改表。
2. `4.*` 数据更新和 `5.*` 视图操作是独立练习；按文件说明执行，避免把删除视图步骤放在查询之前。
3. `6.*` 需要有创建用户和授权权限的管理账号。示例口令不是个人密码；只用于本地练习。
4. `7.a` 创建独立的约束演示表，再执行 `7.b` 修改约束。负例语句已注释，应逐条执行并观察拒绝结果。
5. `8.a` 创建审计触发器，`8.b` 通过事务内更新触发并查询记录，`8.c` 删除。MySQL 没有 `ENABLE TRIGGER` 语句。
6. `2.c` 是最后的清理步骤。`9.*` 只记录终端命令，不是 SQL，切勿当作 SQL 执行。

备份可在终端执行 `mysqldump -u root -p --result-file=demo-backup.sql undergraduate_orders_demo`，避免旧版 PowerShell 的重定向编码问题；恢复时进入 `mysql -u root -p undergraduate_orders_demo`，再输入 `SOURCE demo-backup.sql;`。

已修复原脚本的分号/分隔符、全角分号、重复添加主键列、孤立客户编号、无效触发器语法和旧版本集合操作兼容性。运行验证仍待真实 MySQL 环境完成。
